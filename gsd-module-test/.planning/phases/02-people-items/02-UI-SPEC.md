## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps inside PersonTag/ItemRow (gap-1 = 4px) |
| sm | 8px | Gap between form input and Add button (gap-2 = 8px) |
| md | 16px | Panel internal padding, gap between PersonTags in list |
| lg | 24px | Gap between PeoplePanel and ItemsPanel (gap-6 = 24px) |
| xl | 32px | Page-level horizontal padding (p-8 = 32px from App shell) |
| 2xl | 48px | Major section breaks (not used in Phase 2) |
| 3xl | 64px | Page-level spacing (not used in Phase 2) |

Exceptions:
- PersonTag inline padding: `px-4 py-2` (16px / 8px) — comfortable tag pill shape; `py-2` chosen over `py-1` to maintain readable pill height
- ItemRow padding: `px-4 py-2` (16px / 8px) — row height comfort for desktop
- Remove icon button: `size-icon-xs` = 24px × 24px touch target — acceptable for desktop; Phase 4 will upsize to 44px for mobile

Source: RESEARCH.md patterns, `src/components/ui/button.tsx` size definitions.

## Interaction Contract

### PersonForm

- Input: controlled, `type="text"`, `aria-label="Person name"`, `placeholder="Enter a name..."`
- Add button: `type="submit"`, `disabled` when `name.trim().length === 0`
- On submit: trim name, guard empty, dispatch `addPerson(trimmed)`, clear input to `""`
- Keyboard: Enter key on input triggers form submit (native `<form onSubmit>`)
- No inline validation message needed — disabled button is sufficient for empty guard

### PersonTag

- Layout: `flex items-center gap-2 rounded-md border px-4 py-2`
- Name text: `text-sm` (14px / weight 400)
- Remove button: `variant="ghost" size="icon-xs"`, icon `<X />`, `aria-label="Remove {name}"`
- On click: dispatch `removePerson(id)` — no confirmation dialog (non-destructive to bill data; person can be re-added)

### ItemForm

- Two inputs in one form row: label (`aria-label="Item name"`, `placeholder="Item name"`) and price (`aria-label="Item price"`, `placeholder="$0.00"`)
- Add button: `type="submit"`, `disabled` when either field is empty
- On submit: trim label, call `toCents(price)`, guard `isNaN(cents) || cents <= 0`, dispatch `addItem(trimmedLabel, cents)`, clear both fields
- Invalid price: form submit silently rejected (no add occurs, no error message) — this is acceptable for Phase 2; explicit error messages deferred to Phase 3+ polish
- `toCents()` accepts `$12.50`, `12.50`, `$1,234.56` — user does not need to format price

### ItemRow

- Layout: `flex items-center justify-between rounded-md border px-4 py-2`
- Left: `flex gap-4` — label (`text-sm`) + price (`text-sm text-muted-foreground`)
- Right: Remove button `variant="ghost" size="icon-xs"`, icon `<Trash2 />`, `aria-label="Remove {item.label}"`
- On click: dispatch `removeItem(item.id)` — no confirmation dialog

### Cascade Delete (Plan 02-03)

- No UI change — purely a Zustand store upgrade
- `removePerson` atomically removes person from `people` AND clears their ID from all `item.assignedTo` arrays in a single `set()` call
- No toast, confirmation, or visual indication required for the cascade — it is silent and correct

## Accessibility Contract

- All icon-only buttons carry explicit `aria-label` — required because buttons contain only SVG, no text
- All form inputs carry `aria-label` — required for screen reader association
- Form submit via Enter key works natively via `<form onSubmit>` wrapping both PersonForm and ItemForm
- Focus ring: inherited from shadcn Button and Input — `focus-visible:border-ring focus-visible:ring-3 focus-visible:ring-ring/50`
- Disabled Add button (`disabled` attribute): `pointer-events-none opacity-50` via shadcn CVA — visually and interaction-disabled
